model_id
The response schema now sends a one-value enum taken from CONFIGURED_MODEL (grok-4.3). JSON Schema const is not assumed to be accepted by the strict structured-output subset, so it is not sent. The prompt says to return that exact id. The parser still rejects any other id and does not rewrite the raw text. The HTTP model field remains a separate check.

Examples:
  model_id grok-4.3 and HOLD at 100% cash -> explicit_hold
  model_id paper-v2-allocation -> model_id_mismatch, raw text kept
  missing model_id -> malformed_json
  JSON id grok-4.3 but HTTP model grok-other -> provider_model_mismatch
  the stored first-call reply -> still model_id_mismatch
  that reply with only model_id changed to grok-4.3, in a temporary log -> explicit_hold
